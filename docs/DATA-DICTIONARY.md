# 广告曝光有效性与费用结算数据定义

原始行=采信事件+无效曝光+重复回调+其他隔离+空行。原始费用-合法扣减=应付。CPM单位为CNY/千次，先按渠道和北京时间账日求和，再HALF_UP舍入到分。扣减额采用原始舍入总额与净额之差，保证分币守恒。机器事件优先于频次，机器事件不消耗频次；频次按渠道、账日、用户计数。冲销事件本身不计曝光，不占频次，须不早于原事件且渠道相同。ID保留为字符串。

按曝光ID裁决重复与冲突，按时间及ID确定日频次，再聚合有效CPM。冲销引用采信的原曝光，同一曝光最多冲销一次，费用回到原曝光账日。

## 同一曝光ID多份回执的裁决

同一曝光ID出现多份回执时，不整组隔离、也不按回执到达先后采信，而是按确定性优先级为正式账单选出唯一采信版本：

1. 机器标记 `bot=1` 的回执任何情况下不得进入账单，先做机器分层（依据码 `BOT_EXCLUDED`）。
2. 非机器回执之间取事件时间 `at` 最早者（依据码 `EARLIEST_EVENT_TIME`）；到达顺序不参与裁决。
3. 事件时间相同则以物理来源行号最小者兜底（依据码 `LINE_ORDER_TIE_BREAK`），保证同批输入结果可复算。
4. 一组回执全部为机器流量时账单零采信，整组隔离（依据码 `ALL_BOT`）。
5. 字段完全相同的重复回执去重，保留来源行最小者，其余记 `DUPLICATE`。

裁决结果写入 `adjudications`：每组含 `event_id`、是否采信 `adopted`、采信行 `adopted_line`、依据码列表 `basis` 与全部 `versions`（每份回执的来源行、是否采信、机器标记、时间及原值）。未采信版本按机器/非机器分别记 `CONFLICT_BOT`、`CONFLICT_VERSION` 进隔离区，并回填所属 `event_id` 与 `adopted_line`。所有回执（含未采信版本）完整保留，证据 CSV 以“裁决/裁决版本”类别归档，冲突裁决不丢记录。

原始行号对应 CSV 解析器的物理末行。UTF-8 BOM 与 GB18030 均支持，坏行进入隔离区，结构性错误返回422。空文件、仅表头和全空记录分别返回不同原因码。金额与用量使用 Decimal，对外以字符串返回。编码和编号按字符串保留。

run_id 由输入摘要、参数和规则版本生成；revision 为人工复核版本。证据 CSV 含运行号、来源行、原因码、原始字段及最终结论。
